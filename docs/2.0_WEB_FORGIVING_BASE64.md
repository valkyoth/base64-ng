# 2.0 WHATWG Forgiving Base64

Status: Public through Commit 16 as an ordinary compatibility surface.

`web::FORGIVING` implements the WHATWG Infra Standard's forgiving Base64
decode algorithm. It is intentionally separate from the strict RFC 4648
presets and from the expert `compat` configurations.

## Exact Algorithm

For an input `&str`, the decoder:

1. removes ASCII tab, line feed, form feed, carriage return, and space;
2. when the remaining length is divisible by four, removes at most two
   trailing `=` code points;
3. rejects a remaining length congruent to one modulo four;
4. rejects every remaining code point outside ASCII alphanumeric, `+`, and
   `/`; and
5. decodes six-bit groups while discarding the final four or two unused bits.

The final rule deliberately accepts noncanonical unused bits. For example,
both `YQ` and `YR` decode to `a`. This is exact web compatibility, not strict
RFC 4648 canonical decoding.

## API Boundary

`web::FORGIVING` accepts `&str` and provides:

- transactional `validate`, `decoded_len`, `decode_into`, and allocating `decode_to_vec`
  operations;
- an allocation-limited vector operation; and
- a heapless `ForgivingDecoder` for externally partitioned strings and short
  output buffers.

Malformed content is reported only as `ForgivingError::InvalidInput`.
Resource, lifecycle, and internal backend-integrity errors remain
distinguishable. One-shot helpers reject a zero-progress or impossible finish
state rather than risking an unbounded retry loop. One-shot validation and
exact sizing finish before destination writes, so every one-shot error leaves
the destination unchanged. Incremental output already reported as produced is
committed in the normal streaming manner.

This is an ordinary API. Its state derives `Debug`, does not wipe on drop, is
not constant-time, and must not process classified keys, bearer tokens,
passwords, or other secret-bearing input. It is not exported from `secret::*`.

## Expert Compatibility Is Different

The `compat` module names all accepted combinations of padding-indifferent and
noncanonical-trailing-bit behavior for Standard and URL-safe alphabets. These
values are `Base64<RuntimeSpec>` ordinary codecs matching exact-pinned
`base64` 0.23.0 policy semantics. They do not remove whitespace and they are
not WHATWG forgiving Base64. Every such setting is ineligible for secret
processing.

## Evidence

The locked fixture corpus is
`tests/fixtures/whatwg-forgiving-base64.txt`. It includes the WHATWG `YQ`/`YR`
noncanonical-bit example, every WHATWG ASCII whitespace code point, omitted
and canonical padding, impossible lengths, malformed padding, non-Standard
symbols, non-ASCII input, and browser interoperability cases.
The focused gate pins its SHA-256, so fixture changes require an explicit
reviewed checksum update.

Rust tests execute every fixture through transactional one-shot decode and at
every incremental split with one-byte output. Strict presets are required to
reject web-only inputs. An independent bit-level oracle exhausts every unused
trailing-bit value. Repository-only differential tests compare every named
expert configuration against exact-pinned `base64` 0.23.0.

The same fixture corpus is evaluated by native `atob` in Node/V8,
Chromium/Blink, Firefox/SpiderMonkey, and Safari/WebKit. The wasm smoke also
executes `web::FORGIVING`, so browser runs validate both the Rust wasm result
and the browser-native result. Missing local browsers are reported as skipped;
release evidence must identify the environments that actually ran.

Run the focused core gate with:

```sh
scripts/check-2.0-web-forgiving.sh
```

Run all locally available browser evidence with:

```sh
scripts/check-2.0-web-forgiving.sh --browsers
```

The normative algorithm source is the [WHATWG Infra Standard forgiving Base64
section](https://infra.spec.whatwg.org/#forgiving-base64).
