# 2.0 Formatting, Append, And Chunk Contracts

Status: implemented in Commit 15 for the emerging 2.0 API.

## Lazy Display

`Base64::display(input)` checks encoded-length arithmetic before returning an
`EncodedDisplay`. The wrapper copies the validated codec settings and borrows
only `input`, so it works with built-in constants and temporary runtime codec
values. The Rust lifetime prevents the borrowed input from being dropped or
mutated while the wrapper remains live.

Formatting synthesizes at most one four-byte Base64 quantum on the stack at a
time and performs no heap allocation. It does not replace or suppress an
encoding failure: constructor preflight returns `OneShotError`, while the
`Display` implementation can subsequently return only `fmt::Error` from the
formatter or an impossible validated-ASCII invariant failure. `Debug` reports
metadata without including the borrowed plaintext.

`EncodedDisplay` is an ordinary API, not a redacted or secret-bearing value.
Its `Display` output is the complete encoded input and may therefore disclose
encoded credentials if callers send it to logs.

## Formatter Writes

`Base64::encode_to_fmt(input, writer)` uses `core::fmt::Write` and returns the
number of bytes passed through fully successful `write_str` calls. On failure,
`FormatWriteError::confirmed` returns the same confirmed lower bound.

This is intentionally a prefix-committing contract. The formatter API does
not report whether a failing `write_str` call partially changed its sink.
Consequently, bytes from the failing call are excluded even when an
adversarial formatter performed visible partial mutation. The crate cannot
roll back a third-party formatter.

For exact progress, `CountedSink::write` has a stronger contract: `Ok(count)`
reports the exact accepted prefix and `Err` accepts zero bytes from that call.
`Base64::encode_to_counted` handles short writes, rejects zero progress and
invalid counts, and reports exact prior progress through
`CountedWriteError::committed`. A sink that can mutate before returning `Err`
must not implement this trait.

## Controlled Append Rollback

With `alloc`, `Base64::encode_append` appends encoded ASCII to an existing
`String`, and `Base64::decode_append` appends ordinary plaintext to an existing
`Vec<u8>`. Both return the new suffix length, not the total destination length.

The methods check exact output and total-length arithmetic before mutation,
use `try_reserve_exact`, preserve every byte in the original prefix, and keep a
rollback guard active until success. Every returned crate error and unwinding
panic restores the entry length. Capacity growth, bytes left in spare
capacity, allocator side effects, process-aborting allocation failure, and
foreign observation during unwinding are outside this rollback claim.

Decode validates the complete encoded input before allocation or plaintext
materialization. Append sources must not alias destinations whose growth may
reallocate; safe Rust borrowing normally enforces this requirement.

## Encoded Chunks

`Base64::encoded_chunks(input)` checks output-length arithmetic, copies the
validated settings, and returns an `EncodedChunks` iterator borrowing only the
input. Every item is an owned `EncodedChunk` containing one synthesized output
quantum. This is not zero-copy: Base64 output does not exist inside the
plaintext input.

Complete chunks contain four bytes. An unpadded final chunk contains two or
three bytes; a padded final chunk contains four bytes with canonical `=`
padding. Empty input yields no chunks. `ExactSizeIterator::len` reports
remaining synthesized chunks, not bytes.

## Evidence

- all strict built-in profiles and a runtime custom alphabet over every input
  length from 0 through 193;
- independent one-shot comparison for every synthesized chunk sequence;
- partial formatter mutation and confirmed-prefix accounting;
- short, zero-progress, failing, and invalid-count counted sinks;
- injected reserve failures, post-mutation crate errors, and unwinding panics;
- a dedicated global-allocation counter around display and formatter calls;
- external API and compile-fail lifetime tests in the Commit 15 gate.
