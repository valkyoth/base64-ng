# 2.0 Const Transforms And Bounded Buffers

Status: implemented in Commit 13 for the `2.0.0` candidate.

Commit 13 preserves compile-time and allocation-free transforms without
carrying the 1.x buffer cleanup ambiguity into 2.0. Const transforms operate
on one immutable validated `CodecSettings` value. Bounded ordinary and secret
storage use separate public types and separate destructor contracts.

## Const Transforms

The four strict built-in presets and every successfully built runtime codec
provide `encode_array` and `decode_array`. The input and output lengths are
const generic parameters. The output length must equal the exact result length;
these methods do not treat it as spare capacity.
This exact output length rule is checked before transformation.

```rust
use base64_ng::STRICT_STANDARD_PADDED;

const ENCODED: [u8; 8] = match STRICT_STANDARD_PADDED.encode_array(b"hello") {
    Ok(output) => output,
    Err(_) => panic!("reviewed literal must encode"),
};
const DECODED: [u8; 5] = match STRICT_STANDARD_PADDED.decode_array(&ENCODED) {
    Ok(output) => output,
    Err(_) => panic!("reviewed literal must decode"),
};

assert_eq!(&ENCODED, b"aGVsbG8=");
assert_eq!(&DECODED, b"hello");
```

Custom alphabets remain validated before const transformation:

```rust
use base64_ng::{CodecBuilder, DecodePadding, EncodePadding};

const TABLE: [u8; 64] =
    *b"./ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";
const CUSTOM: base64_ng::Base64<base64_ng::RuntimeSpec> =
    match CodecBuilder::from_table(TABLE) {
        Ok(builder) => match builder
            .encode_padding(EncodePadding::Unpadded)
            .decode_padding(DecodePadding::Forbid)
            .build()
        {
            Ok(codec) => codec,
            Err(_) => panic!("reviewed codec policy must build"),
        },
        Err(_) => panic!("reviewed alphabet must validate"),
    };
const ENCODED: [u8; 8] = match CUSTOM.encode_array(b"custom") {
    Ok(output) => output,
    Err(_) => panic!("reviewed literal must encode"),
};

assert_eq!(&ENCODED, b"W1TxbE7r");
```

`ConstTransformError` deliberately distinguishes arithmetic overflow,
malformed ordinary input, and an exact output-length mismatch. Merely calling
a const transform yields a typed `Result`. A caller promotes malformed static
data to a compiler diagnostic only by matching the result in a constant and
panicking on `Err`, as the examples do. Runtime calls return the same typed
diagnostic and do not panic inside the crate.

Const decode is an ordinary early-return validator with detailed input errors.
It is not constant-time-oriented and must not process secret-bearing input.

## Ordinary Bounded Storage

`EncodedArray<CAP>` and `DecodedArray<CAP>` own `[u8; CAP]` plus a private,
checked initialized length. Their visible prefix is available through
`as_bytes`; `into_parts` explicitly exposes the complete array and length.
`Base64::encode_bounded` and `Base64::decode_bounded` fill these values through
the transactional one-shot operations.

Both ordinary types are `Copy`, have visible `Debug`, and deliberately do not
implement `Drop`. They are not suitable for keys, tokens, passwords, or other
secret material merely because they are stack-backed. Bytes after the visible
prefix are not part of the public value. Codec-produced arrays initialize that
tail to zero, while `from_array` preserves caller-supplied tail bytes.

## Secret Bounded Storage

`secret::SecretArray<CAP>` is available with the `secrets` capability and is
non-Clone and non-Copy. `Debug` and `Display` redact its
bytes, and access requires the explicitly named `expose_secret` method. Its
constructor wipes tail capacity before returning. Invalid lengths wipe the
complete supplied array, while `clear` and `Drop` wipe the complete backing
capacity and reset the visible length.

This is a bounded storage primitive, not a secret transform. Commit 19 owns the
fixed-work secret decoder and protected staging contract. Constructing a
`secret::SecretArray` from an ordinary array cannot erase historical compiler copies,
registers, stack frames, swap, snapshots, or crash dumps. The crate's
best-effort wipe limitations continue to apply.

## Stack And Code-Size Bounds

The bounded value footprint is `CAP` bytes plus one aligned `usize` length.
Current representative 64-bit source bounds are 72 bytes for
`EncodedArray<64>`, 264 bytes for `DecodedArray<256>`, and 1,032 bytes for
`secret::SecretArray<1024>`. Tests derive these values with `size_of`; they are object
footprints, not measurements of the complete dynamic call chain.

Const results are evaluated into static data and add no runtime transform
state. `scripts/check-2.0-const-buffers.sh` compiles release evidence and
records the resulting fixture artifact size for the exact toolchain and target.
That artifact size is comparative evidence only and is not a cross-target
binary-size guarantee.

Large capacities remain a caller stack-budget decision. No constructor hides
heap allocation, and no 2.0 bounded operation reallocates.

The ordinary constructor invariant is also covered by the bounded Kani harness:
every successful value has `len <= CAP`, every rejection reports the original
length and capacity, and `remaining_capacity` cannot underflow.

## Migration

- Replace 1.x `Engine::encode_array` with a strict preset or validated runtime
  codec `encode_array` call and handle `ConstTransformError` explicitly.
- Replace 1.x capacity-style `decode_array` tuples with exact-output
  `decode_array`, or use `decode_bounded` when spare capacity is intentional.
- Replace ordinary 1.x `EncodedBuffer` and `DecodedBuffer` with
  `EncodedArray` and `DecodedArray`.
- Do not migrate secret-bearing 1.x buffer use to an ordinary array. Use
  `secret::SecretArray` only for bounded storage and wait for the Commit 19 secret
  transform when fixed-work decode is required.
