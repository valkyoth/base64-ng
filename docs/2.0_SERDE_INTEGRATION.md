# 2.0 Serde Integration

`base64-ng-serde` keeps `serde` outside the dependency-free core while binding
field adapters to the validated 2.0 codec specifications.

## Representation

- Human-readable serializers receive Base64 text through `serialize_str`.
- Binary serializers receive the same Base64 text through `serialize_bytes`.
- Binary formats do not receive raw decoded bytes.
- Deserializers are asked for borrowed strings or bytes where supported. An
  owned value supplied by the upstream format is decoded in place without a
  second Base64-owned encoded-input copy. Secret adapters additionally own an
  RAII guard that initializes and wipes the complete transferred allocation,
  including spare capacity, before deallocation on success, error, or unwind.

The compatibility modules `standard`, `standard_no_pad`, `url_safe`,
`url_safe_no_pad`, `mime`, and `pem` retain their 1.x signatures. Decoded
output is one exactly sized `Vec<u8>`. MIME and PEM body adapters validate line
layout and stream non-separator bytes into the decoder rather than allocating
a compacted encoded-input buffer.

## Bounded Ordinary Fields

The corresponding `bounded::*` modules deserialize into
`DecodedArray<CAP>`. Base64-owned decoded output is therefore fixed-capacity
stack storage. `deserialize_exact` additionally requires the decoded length to
equal `CAP`.

```rust
use base64_ng::DecodedArray;

#[derive(serde::Deserialize, serde::Serialize)]
struct Message {
    #[serde(with = "base64_ng_serde::bounded::standard")]
    payload: DecodedArray<32>,
}
```

This bound does not constrain memory allocated by JSON, CBOR, or another data
format before its deserializer delivers the encoded value.

## Secret Fields

The `secrets` feature provides `secret::standard`,
`secret::standard_no_pad`, `secret::url_safe`, and
`secret::url_safe_no_pad`. They use `SecretArrayFrame<CAP>` and return a
non-Clone, wiping `SecretArray<CAP>` only after the fixed-work result gate.
All failures use the same opaque `invalid secret base64 input` message.

General Serde parsing is timing-variable and may allocate before input reaches
the adapter. The secret timing boundary starts only at input delivery. Wrapped
MIME/PEM secret modules are deliberately absent because line-layout parsing is
not part of the fixed-work secret codec policy.

Secret serialization explicitly exposes bytes as visible Base64 text. Use
`deserialize_with` instead of `with` when a secret field must never be
serializable. An RAII guard wipes the complete temporary encoded allocation on
normal return, serializer error, or unwinding serializer panic. Copies retained
by the serializer or output format are outside the crate's ownership and must
be handled by the application. Borrowed encoded input remains owned by the
upstream deserializer and cannot be wiped by this crate.

## Evidence

`scripts/check-2.0-serde.sh` enforces 2.0 codec routing, rejects legacy engine
and encoded-input-copy patterns, and runs profile, bound, binary-mode, secret,
owned-input and serializer-unwind cleanup, clippy, documentation, and
no-default-feature checks. It does not prove the allocation or timing behavior
of an upstream Serde data format.
