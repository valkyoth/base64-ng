# 2.1.0 Compatibility Baseline

Status: Commit 1 development inventory; external review pending.
Baseline: signed `v2.0.4`, `816da2e1e4a66c913057c86d149068f1c88776bf`.
The parent immediately before Commit 1 is
`cb29f978a5130e5b37acd8d5edfe5ff6adfc6d82`.

## Versions And Publication

Core and sanitization were published at 2.0.4; the other eleven companions and
npm loader at 2.0.3. All thirteen Rust packages, the internal WASM artifact,
and the npm package now report 2.1.0 for development. Internal path dependency
requirements and all checked-in lockfiles follow that version. Third-party
dependencies and checksums are unchanged.

`release-crates.toml` uses `development-blocked`, with no package selected.
Workspace manifests additionally use `publish = false`, and npm uses
`private: true`; direct publication must not bypass the development policy.
The internal WASM crate remains permanently unpublished. Package construction,
ordinary tests, and API checks are still allowed. Candidate/release gates are
blocked until an explicitly reviewed release preparation removes these blocks.
No pentest PASS or completed 2.1.0 hardware campaign is asserted here.

## Public Route Inventory

| Surface | Current route | Compatibility contract |
| --- | --- | --- |
| Root `encode`/`decode`, historical `Engine` | Historical encode/decode backends and scalar fallback | Existing `EncodeError`/`DecodeError`, sizing and error precedence; scalar `decode_slice` can leave a prefix on error |
| `Base64<S>::encode_into` | `src/v2/ordinary.rs` scalar encoding loop | Exact sizing before writes, entire output unchanged on returned errors |
| `Base64<S>::decode_into`, `validate`, `decoded_len` | Incremental validation into scratch, then separate scalar writing | `OneShotError`, original positions, validation before output-capacity failure; destination unchanged on errors |
| Allocating, bounded, append, `Base64String` | Canonical methods; some repeat validation | Validation before output reservation, allocation limits, prefix/length rollback, immutable ordinary encoded owner |
| In-place ordinary | Full prevalidation then scalar compaction or reverse encoding | Entire buffer unchanged on returned errors; residual ordinary storage is not wiped |
| Incremental encoder/decoder | Bounded quantum states | Exact accepted/produced progress, per-call validation/mutation, absorbing failure, finish/reset and partial-output semantics |
| Sync I/O, Tokio, Bytes | Shared states or historical adapters as documented | Framing, retry, cancellation, bounded queues, external prefix delivery and cleanup contracts remain API-specific |
| Serde and protocol companions | Explicit codec/protocol policies | Grammar, limits, original error positions and visibility stay distinct from strict one-shot behavior |
| Secret/CT, protected storage, sanitization/subtle/derive | Separate fixed-work and cleanup boundaries | Opaque secret errors, explicit exposure, staging, protection and drop/unwind contracts unchanged |
| WASM loader | Scalar and simd128 artifacts with JS ownership/limit checks | Transactional Into operations, hostile-input rejection, disposal, exact artifact selection and runtime limitations |

The inventory is descriptive, not a new guarantee for a historical surface.
New ordinary validation options must not alter grammar or silently select
secret behavior. Checked execution, health latches, quarantine/retry, static
tokens, and generation checks remain mandatory where currently promised.

## Hardware And Reference Paths

The existing admission scope is retained: SSSE3/SSE4.1 and AVX2 ordinary
encode/decode, AVX-512 VBMI encode with strict decode exact/static only,
little-endian AArch64 NEON, wasm simd128, and exact Linux/SpacemiT X60 RVV.
Existing CPU/OS checks, length thresholds, KATs, and cleanup remain unchanged.
SVE, other RISC-V profiles, big-endian fallback, and unsupported hosts acquire
no additional admission through this metadata checkpoint. Windows native
evidence is planned separately; a hosted CI pass is not a performance claim.

The independent RFC oracle and frozen API inventories remain reference input.
Historical scalar-reference test wrappers share production scalar code and
are not independent oracles. Preserve the distinction during optimization.

## Compiler And Benchmark Baseline

Release compiler: Rust 1.98.1. MSRV: Rust 1.90.0. API extraction:
`cargo-public-api 0.52.0`, `nightly-2026-07-13`; Kani keeps its separate pinned
toolchain. All are unchanged by Commit 1.

Historical performance bundles under `performance-baselines/` retain their
own source/toolchain/host identities. Their numbers are not fresh 2.0.4/2.1.0
comparisons. Commit 2 must capture paired public-API baselines on the same
compiler, hardware and features, including default scalar, cold/warm, small,
malformed, streaming and in-place cases. It must provide a short comparison
runner and freeze noise/regression criteria before optimization. Existing
SIMD-versus-scalar admission alone cannot establish a version-to-version gain.

## Verification

version-policy mutations without contacting registries. API checks compare all
13 current snapshots to the released baseline. The downstream compatibility
fixture is compiled unchanged against both the signed baseline and development
tree with the active toolchain and MSRV. Focused test, lint, documentation and
lockfile checks supplement these controls; results are recorded in the plan.
