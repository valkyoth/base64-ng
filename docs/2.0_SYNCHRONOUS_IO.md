# 2.0 Synchronous I/O Contract

Commit 35 rebuilds the four `std::io` adapters over the same heapless
incremental encoder and decoder used by the canonical 2.0 APIs. The adapters
own external I/O queues and framing state only. They do not implement Base64
quantum, alphabet, padding, tail, or canonicality logic independently.

## Progress

`Encoder` and `Decoder` implement `std::io::Write`. Every input byte counted by
a successful `write` return is irrevocably prefix-committed. The caller must
resume at exactly that byte offset. Produced output may still be held in the
adapter's bounded queue until a later write, `flush`, or `finish` drains it.

The decoder feeds the shared incremental state at quantum boundaries. If a
malformed quantum follows valid quanta in one call, it returns the exact valid
prefix as successful progress, latches failure, and rejects every later
operation. If no byte from that call was accepted, it returns the original
`OperationError`, including the absolute ordinary-input position.

## External Writer Failures

Short writes and errors that occur before a third-party writer changes external
state are retryable. The pending output remains queued. A writer is also able to
change a file, socket, device, or other side effect and then return `Err`. Rust's
`Write` contract gives this adapter no committed-byte count for that failure.
The adapter cannot infer or undo the side effect, and retrying may duplicate it.
Applications requiring transactional external output must supply a
transactional sink or stage the complete result before transfer.

An inner writer that returns a count larger than the supplied slice is treated
as an invalid progress report. The adapter fails closed and never uses that
count to discard unverified queue bytes.

## Framing And Secrets

For padded input, `DecoderReader` reads only enough bytes to complete the next
four-byte quantum. Terminal padding therefore leaves an adjacent frame unread.
Unpadded input uses EOF as its finalization boundary.

The synchronous stream module is an ordinary, input-dependent API. It does not
offer an unbounded secret decoder that releases plaintext before complete-frame
validation. Secret-bearing payloads must be collected under an application
frame limit and decoded through bounded staged `ct` or 2.0 secret APIs. Internal
adapter state and queued output are cleared through the reviewed wipe boundary
on drop and absorbing codec errors, but this cleanup does not make ordinary
streaming constant-time or transactional.

## Evidence

`scripts/check-2.0-sync-io.sh` verifies that:

- all four adapters delegate to `EncoderDriver` or `DecoderDriver`;
- adapters contain no independent input-quantum arrays or one-shot codec calls;
- one-byte reads, short writes, retry, EOF, adjacent frames, malformed suffixes,
  and exact prefix progress pass the sync-stream suite;
- stream error positions agree with the canonical one-shot decoder; and
- adversarial writer side effects and invalid progress reports remain explicit.
