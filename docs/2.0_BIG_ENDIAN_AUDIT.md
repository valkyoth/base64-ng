# 2.0 Big-Endian Byte-Order Audit

Status: Commit 31 portable-path audit.

## Scope

This audit covers ordinary scalar encode and decode, incremental states,
transactional and in-place transforms, wrapping and compatibility policies,
secret storage, bounded secret encode and decode, cleanup, and backend
reporting. The executable evidence targets `s390x-unknown-linux-gnu` and
`powerpc64-unknown-linux-gnu` under QEMU user mode.

## Byte-Order Invariants

- Base64 scalar arithmetic reads and writes individual `u8` values. It does
  not reinterpret input as native-endian multi-byte integers.
- Incremental state retains byte arrays, byte counts, and public `usize`
  positions. A position's in-memory representation is never serialized as
  Base64 data.
- One-shot and in-place transforms use explicit byte indexes and shifts on
  promoted `u8` values. Reverse traversal during in-place encode changes only
  overlap safety, not byte order.
- Wrapping inserts or removes literal ASCII bytes. Legacy whitespace handling
  classifies individual bytes and retains original byte indexes.
- Secret encode and decode use the same byte-value equations in fixed-work
  scalar loops. Secret storage and cleanup operate over `[u8]`; cleanup never
  converts a secret byte sequence into a native-endian word.
- Runtime dispatch exposes no `s390x`, PowerPC64, or big-endian AArch64
  accelerated candidate. Both ordinary operations and secret processing stay
  scalar on the audited targets. Big-endian runtime reports must remain scalar active.

## Native-Width Operations

Native-width pointer loads and stores are confined to architecture-specific
SIMD modules. The x86 and wasm modules cannot compile for the audited native
targets. The NEON module and every NEON dispatch edge require both
`target_arch = "aarch64"` and `target_endian = "little"`.

`src/cleanup.rs` converts initialized `MaybeUninit<u8>` spare capacity to a
byte pointer. This is a byte-for-byte cleanup boundary, not a numeric
reinterpretation. No portable codec source uses `from_ne_bytes`,
`to_ne_bytes`, `swap_bytes`, `transmute`, or a raw multi-byte integer load.

## Evidence Boundary

`scripts/validate-big-endian-byte-order.sh` enforces the portable-source rules
above. `scripts/check_big_endian_qemu.sh --all` runs complete default,
all-feature, and no-default-feature test suites for both targets, including
RFC vectors, malformed input, incremental and stream behavior, in-place
transforms, secret cleanup, backend reporting, and the dedicated
`tests/big_endian.rs` contract.

QEMU proves functional behavior under emulation. It does not prove physical
cleanup, timing, side-channel behavior, microarchitectural behavior, or real
hardware performance. The project therefore admits no big-endian accelerated
backend without a conforming real-hardware report and separate backend review.
