# 2.0 Formal Verification Boundary

Commit 50 expands the Kani campaign over the final 2.0 core. The complete,
machine-checked harness inventory is [`kani/harnesses.tsv`](../kani/harnesses.tsv).
Every entry has one resource class, source file, and deliberately narrow claim.

## Proof Sets

| Set | Harnesses | Release use | Default limit |
| --- | ---: | --- | --- |
| Normal | 43 | Required through `scripts/check_kani.sh` | 5 minutes per harness, 8 GiB process virtual memory |
| Advanced | 19 | Required on the release-evidence host | 10 minutes per harness, 16 GiB process virtual memory |
| Exploratory | 6 | Optional; never counted as release proof | Explicit opt-in only |

`scripts/validate-kani-proof-inventory.py` fails if source and the registry
drift, if a normal harness is advanced-gated, or if a harness silently becomes
exploratory. The two exploratory wrapped-input harnesses are retained because
they are useful experiments, but earlier runs showed that their unrestricted
SAT instances can consume workstation-scale memory for hours. Deterministic,
property, fuzz, and Miri evidence covers those public wrapped surfaces.

Both Kani runners retain the verifier version, compiler identity, exact
commands, selected harnesses, output, elapsed-resource report, peak resident
memory when GNU `time` is available, unsupported-construct warnings, status,
and checksums under `target/release-evidence/kani/`. Generated evidence is not
committed or packaged; the release process archives the exact candidate's
directory separately.

## Proven Claims

The normal set proves bounded arithmetic and state invariants for:

- encoded and decoded capacity formulas;
- runtime-alphabet constructor indexes and per-position visible, non-padding,
  uniqueness constraints;
- runtime codec policy compatibility and secret-policy eligibility;
- one-shot, incremental, finalization, and in-place progress bounds;
- validation-before-mutation rollback and mathematical overlap preflight;
- fixed queue cursors and initialized-before-visible output commits;
- scalar quantum and canonical tail arithmetic;
- constant-time-oriented result bounds and caller-buffer cleanup on error;
- portable 12-to-16 and 16-to-12 SIMD block arithmetic, per-lane mapping,
  all-lane validity reduction, and wrapper cursors for each admitted width.

The advanced set additionally proves full-symbolic encode refinements of all
four strict presets against a deliberately independent fixed-array RFC 4648
oracle. Decode correctness is composed from symbolic built-in-alphabet lookup,
all-bit production packing, state invariants, and exhaustive/differential
tests. Integrated incremental/in-place Kani known answers and production
rollback plus borrowed-frame integration are retained as exploratory because
validator/fixed-work expansion exceeds 16 GiB. Required proofs also
cover canonical rejection,
secret frame release gating, absorbing secret-size failures, and the abstract
assurance protocol described below.

## Teardown And Journal Model

`src/kani_assurance_proofs.rs` models the reachable four-axis teardown product:
wipe evidence, physical-protection transition, accounting, and allocation
disposal. It proves that `Closed` requires policy-sufficient wipe evidence,
confirmed protection removal, reconciled accounting, applied disposal, and no
addressable owner. It also proves:

- quarantine preserves the exact earliest pending stage and existing wipe
  evidence without treating ownership transfer as a wipe;
- applied or indeterminate non-idempotent journal operations cannot replay;
- accounting applies at most once;
- generation termination rejects every old operation identity;
- journal progress is monotonic and bounded;
- a tombstone retains identity only, never an addressable owner.

This is a finite in-memory protocol model for one volatile provider-instance
generation. It is not proof of persistence, crash recovery, operating-system
protection, allocator behavior, an external unsafe provider, or recovery after
process termination. Base 2.0 ships no persistent teardown provider.

## SIMD And Unsafe Boundary

Kani proves the portable model, not target intrinsics, inline assembly,
register cleanup, CPU feature detection, or generated machine code. Real
backends are connected to that model by direct block differential tests and
the x86, NEON, wasm, RVV, SVE, QEMU, and generated-assembly gates documented in
[`SIMD_ADMISSION.md`](SIMD_ADMISSION.md) and
[`2.0_DISPATCH_AND_PERFORMANCE_MATRIX.md`](2.0_DISPATCH_AND_PERFORMANCE_MATRIX.md).

The published core has no `Vec::set_len` transition. It does not use
`MaybeUninit` for codec output or direct SIMD output; the sole production
`MaybeUninit` use writes vector spare capacity during cleanup and never reads
it. Companion `BufMut` advancement and panic restoration are safe-API
boundaries tested with adversarial sinks. Miri, sanitizers, panic injection,
generated assembly, and the unsafe inventory remain required because Kani
does not directly establish those implementation-level facts.

## Unsupported Constructs

Kani 0.67.0 reports `caller_location`, one foreign-function boundary, and
single-thread atomic fences during whole-crate code generation. Required
harnesses do not call the foreign architecture boundary. Compiler and wipe
fences are intentionally covered by generated-code review and platform tests;
Kani treats the single-thread fences sequentially. Kani does not support
concurrency, persistence, signals, process crashes, or downstream wasm JIT
behavior, and no release claim assigns those properties to this proof set.
