# 2.0 Incremental Padded Decoder

Release target: `2.0.0`

Commit 10 implements the private heapless ordinary decoder for strict,
canonical padded Base64. It does not change the frozen 1.3.9 public API.
Commit 11 extends the same bounded state model with an explicitly selected
strict unpadded policy, documented in
[`2.0_INCREMENTAL_DECODER_FINALIZATION.md`](2.0_INCREMENTAL_DECODER_FINALIZATION.md).
Padded mode still does not accept missing, optional, or excess padding.

## State Bound

`DecoderState` owns one complete validated codec setting, at most three
incomplete encoded symbols with their original absolute indexes, at most three
pending plaintext bytes, terminal-padding state, exact source position state,
and no allocation. Partial input and pending output are mutually exclusive.
The ordinary state has no `Drop` implementation, wiping, or secret feature
overhead. Commit 20 defines a separate secret decoder state.

## Update Contract

`update(input, output)` preflights the complete absolute source span, then
validates the exact prefix that can fit in the fixed state and destination.
Only after that validation succeeds does it commit source progress and write
output. Consequently, an input failure in the current call leaves that call's
destination unchanged; output reported by earlier successful calls remains
committed.

- `Progress::input_consumed` is the exact accepted encoded prefix.
- `Progress::output_produced` is the exact initialized plaintext prefix.
- `NeedInput` means all supplied input was accepted and no plaintext is
  pending.
- `OutputFull` means decoded output remains pending. Retrying with one output
  byte always makes progress and never re-consumes encoded input.
- Every input failure is absorbing until `reset` and preserves the first
  detailed error.
- Position overflow is detected before state or destination mutation.

The fixed parser rejects invalid symbols as soon as their position is
accepted, including space, tab, carriage return, line feed, mixed alphabets,
and `=` in a non-terminal position. A complete padded quantum additionally
checks exact padding count and zero unused trailing bits. Once terminal
padding is accepted, the first later source byte is `TrailingData`.

## Finish And Reset

`finish(output)` first drains pending plaintext. A partial encoded quantum
then fails with `TruncatedInput` at the absolute end position; it is never
reported as `NeedInput` after end of input was declared. A complete message
returns `Complete`, and later finish calls return `Complete` with zero
progress. New input after completion is rejected until `reset`.

`reset` clears logical ordinary state and starts one unrelated message at
source position zero. It is not a secret erasure claim.

## RFC 4648 Trace

The locked requirement identifiers come from
[`rfc4648-requirements.json`](../rfc/rfc4648-requirements.json).

| Requirement | Commit 10 evidence |
|---|---|
| `RFC4648-3.1-MUST-NO-UNSOLICITED-LINES` | CR and LF are rejected at every quantum position and every chunk boundary. |
| `RFC4648-3.2-MUST-PAD-BY-DEFAULT` | Partial padded input fails at `finish`; canonical one- and two-pad tails pass. |
| `RFC4648-3.3-MUST-REJECT-NON-ALPHABET` | Every byte outside each selected alphabet, including all ASCII whitespace and mixed Standard/URL-safe symbols, is rejected at every quantum position with its exact index. |
| `RFC4648-3.3-MAY-IGNORE-EARLY-PADDING` | The strict decoder declines this option and rejects early padding. |
| `RFC4648-3.3-MAY-IGNORE-EXCESS-PADDING` | Terminal state rejects the first excess pad as trailing data. |
| `RFC4648-3.4-DEFAULT-NO-GLYPH-FOLDING` | Only exact bytes in the owned validated alphabet are mapped. |
| `RFC4648-3.5-MAY-REJECT-NONCANONICAL` | Non-zero unused bits return `NonCanonicalTrailingBits` at the significant symbol index. |
| `RFC4648-4-24-TO-4X6` | Every valid bounded partition is compared with the independent oracle output. |
| `RFC4648-4-STANDARD-ALPHABET` | Strict Standard RFC Section 10 vectors pass every input/output partition. |
| `RFC4648-4-PADDING-CASES` | No-pad full quanta and canonical one- and two-pad terminal quanta are covered. |
| `RFC4648-5-URL-SAFE-ALPHABET` | URL-safe valid data and mixed-alphabet rejection use the exact Table 2 symbols. |

## Evidence

- RFC 4648 Section 10 vectors run through both strict padded decoders and
  every input/output partition.
- Deterministic bounded binary inputs are encoded by the independent oracle,
  then decoded over every partition.
- Malformed padded inputs are split at every source boundary; error class,
  original index, absorbing state, and failing-call destination atomicity are
  checked.
- Every non-alphabet byte and every forbidden one- or two-byte-tail unused-bit
  value is rejected at every applicable position and chunk boundary.
- Repeated zero-capacity and one-byte retries prove pending output cannot lose,
  duplicate, or re-consume input.
- Debug, release, no-default-features, and Rust 1.90.0 checks cover the same
  state machine.
- Kani proves bounded symbolic progress, fixed-state invariants, and that a
  one-byte retry after `OutputFull` makes output progress.
