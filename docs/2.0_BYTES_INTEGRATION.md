# 2.0 Bytes Integration

Status: implemented in Commit 36 for the 2.0 companion package.

## API Split

`base64-ng-bytes` extends the sealed 2.0 `Base64<S>` codec. It no longer
targets the legacy `Engine<A, PAD>` surface.

`Base64BytesExt::encode_buf` and `decode_buf` are transactional with respect to
caller-visible output. They consume an owned `Buf`, construct one private
result allocation, and return `Bytes` only after the incremental transform and
final validation complete. On error, that allocation is dropped and no output
is returned.

`BytesEncoder` and `BytesDecoder` are resumable prefix-committing adapters for
arbitrary `BufMut` destinations. `BytesStep` reports the exact input prefix
accepted by the transform and output prefix passed to the destination by each
successful call. For a conforming `Buf`, accepted input is also the exact
external cursor movement. `Status::OutputFull` preserves pending core state
for a later retry.

Ordinary decoder output already returned through `BufMut` is irrevocably
visible if a later fragment is malformed. This surface must not be used for
secret-bearing frames. Bounded validate-before-release secret APIs remain in
the core `secrets` capability and protected-memory companions.

## Fragment And Memory Contract

Input is read only through `Buf::remaining`, `Buf::chunk`, and `Buf::advance`.
The adapter never calls `copy_to_bytes`, builds a full-input `Vec`, or otherwise
coalesces fragmented input.

The stateful path owns one initialized 1024-byte scratch array plus the shared
incremental core's constant-size quantum state. It sends only the initialized
scratch prefix to safe `BufMut::put_slice`; this companion contains no unsafe
code and never calls `advance_mut` or `Vec::set_len` itself.

Transactional encode reserves the exact result allocation. Transactional
decode reserves at most the encoded input length, which is an output upper
bound, and transfers that payload allocation into `Bytes`. The `bytes` crate
may add a small ownership header when the visible result is shorter than its
reserved capacity. Allocation-counter evidence therefore requires one payload
allocation, permits only bounded ownership metadata, and rejects any second
payload-sized temporary allocation.

## Limits And Failures

`BytesLimits` applies cumulative input and output limits to both stateful and
transactional operations. The initial reported remainder and every later
`remaining()` window are checked against the cumulative source position before
its chunk is observed. An interior-mutable safe `Buf` therefore cannot pass a
small preflight report and later expand beyond the frame limit. Output-limit
failures include the exact progress committed before the limit became terminal.

Malformed input, limit failures, inconsistent safe `Buf` progress, and core
errors latch stateful adapters failed until explicit reset. The adapter marks
itself failed before invoking downstream buffer methods, so a caught panic
cannot resume partially synchronized state.

`BytesProgress::input_consumed` always means bytes accepted by the transform.
`BytesError::input_cursor_progress` separately reports whether external `Buf`
cursor movement is `Exact(n)` or `Indeterminate`. A custom `Buf` can violate
its safe trait contract by returning from `advance` without moving, by moving a
different amount, or by lying in a later `remaining` call. Once that happens,
the companion can detect inconsistency but cannot reconstruct the caller's
true cursor position. Callers receiving `Indeterminate` must discard the input
cursor, failed adapter, and any prefix output rather than recover by numeric
offset.

Successful `BufMut::put_slice` calls are counted as committed. A hostile unsafe
`BufMut` implementation may mutate and then panic or violate its own
initialization contract; the companion cannot roll back or safely test trait
implementations whose unsafe contract is false. Panic injection uses a valid
implementation that writes initialized bytes before panicking and verifies the
adapter remains closed afterward.

## Evidence

`scripts/check-2.0-bytes.sh` enforces direct chunk routing and rejects known
full-coalescing helpers. It runs:

- one-byte input and output fragmentation for encode and strict decode;
- finite-output retry and exact cumulative progress checks;
- malformed suffixes after a previously committed valid prefix;
- transactional no-output-on-error behavior;
- cumulative input and output limits;
- interior-mutable `remaining()` expansion before chunk exposure;
- invalid safe `Buf` progress in both moved-but-misreported and no-op-advance
  directions, plus downstream `BufMut` panic injection;
- an allocation counter proving no second payload-sized allocation exists;
- default, `no_std + alloc`, release, clippy, and rustdoc matrices.

`scripts/check_miri.sh` additionally runs the adversarial bytes integration
test binary under Miri. Miri checks observable undefined behavior in this test
scope; it does not validate an unsafe third-party `BufMut` implementation that
breaks the trait's required contract.
