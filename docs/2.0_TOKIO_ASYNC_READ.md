# 2.0 Tokio AsyncRead Integration

Status: implemented in Commit 37 for the 2.0 companion package.

## Shared State

`base64-ng-tokio` read-all helpers and `AsyncRead` adapters now accept the
sealed 2.0 `Base64<S: Codec>` surface. `EncoderReader` owns the shared
`EncoderState`; `DecoderReader` owns the shared strict `DecoderState`. The
reader layer no longer contains a second Base64 quantum implementation.

Commit 38 completes the writer migration on the same shared states. Its
accepted/committed progress and backpressure contract is documented in
`docs/2.0_TOKIO_ASYNC_WRITE.md`.

## Reader Boundaries

`EncoderReader::new` and `DecoderReader::new` transform one source through
actual EOF. They may therefore consume every byte returned by the wrapped
reader.

`new_exact` declares one exact source-frame length. It caps every inner poll at
the remaining frame length, finalizes without an overflow probe, and leaves
adjacent bytes unread. EOF before the declared length is
`ErrorKind::UnexpectedEof`.

The `*_reader_to_writer_limited` read-all helpers have a different contract.
They read the entire frame privately and use at most one byte beyond the
configured limit to distinguish an exact-length input from an oversized one.
Generic `AsyncRead` cannot return that lookahead byte. Use `new_exact` or an
already bounded reader when adjacent data must remain unread.

## Poll And Exposure Contract

The adapters are explicit `poll_read` state machines; no internal `async fn`
captures hidden transform locals. Fixed initialized input and output arrays,
the shared transformer, counters, EOF/exact boundary, completion, and failure
state all live in the adapter across `Poll::Pending`.

Pending output drains before the wrapped source is polled again. Input read
from the source and input accepted by the transformer are reported separately
through `input_read` and `source_position`. Malformed input, premature exact
EOF, an inner error, or an impossible progress result latches failure and
clears retained buffers. A later poll returns the absorbing failed-state error.

Ordinary decoded plaintext already returned to a caller cannot be retracted if
a later suffix is malformed. `DecoderReader`, including `new_exact`, is not a
validate-before-release secret decoder. Secret-bearing frames must be bounded,
fully validated, and released through the core `secrets` capability or an
approved protected-memory companion.

## Cleanup

Dropping either reader explicitly clears its fixed input and output arrays and
calls the shared state's explicit best-effort `clear` operation. Delivered
bytes, wrapped-reader copies, caller buffers, registers, caches, swap, and crash
dumps remain outside that cleanup boundary.

## Evidence

`scripts/check-2.0-tokio-readers.sh` rejects legacy codec logic in the reader
module and runs:

- existing read-all and compatibility behavior;
- one-byte source and destination fragmentation;
- `Pending` before and after arbitrary deterministic chunk schedules;
- cancellation by dropping a pending read future and resuming the same state;
- exact-frame adjacent-byte preservation and premature EOF;
- inner errors with partial quantum state;
- malformed suffixes after irrevocably delivered plaintext;
- release-mode tests, clippy, and rustdoc.

`scripts/check_miri.sh` runs the exact-boundary adversarial integration test
under Miri when the pinned nightly Miri toolchain is installed. This evidence
checks observable undefined behavior in that scope; it is not a formal proof
of cancellation safety or complete schedule exploration.
