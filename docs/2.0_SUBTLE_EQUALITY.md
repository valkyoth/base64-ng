# 2.0 Reviewed Subtle Equality Integration

Commit 41 migrates `base64-ng-subtle` from the 1.x ordinary-buffer bridge to
the final 2.0 secret storage and exposure model. The core crate remains free of
runtime dependencies; applications admit `subtle` only through this companion
or directly at their protocol boundary.

## API Boundary

`SubtleSecretEq` is sealed and implemented only for these reviewed 2.0 types:

- `SecretInput`;
- `SecretOutput`;
- `SecretArray<CAP>`;
- `SecretVec` when `alloc` is enabled;
- `ExposedSecret`; and
- `ExposedSecretMut`.

The sole trait method is `subtle_ct_eq_public_len`. It delegates equal-length
bytes to `subtle::ConstantTimeEq` and returns `Choice::from(0)` immediately for
a length mismatch. Length is therefore public. The trait provides no
`subtle_verify` or other boolean convenience method; conversion of `Choice` to
`bool` is a visible protocol decision.

The free `subtle_ct_eq_public_len` helper retains the same explicit contract
for caller-owned slices. `subtle_ct_eq_fixed_width` compares equal-width arrays
without a runtime length branch.

The 1.x compatibility buffers retain their frozen source-compatible methods
during development, but they are not implementations of `SubtleSecretEq`.
Final 2.0 secret owners provide neither ordinary `PartialEq` nor dependency-
free equality sugar. A secret comparison therefore requires the reviewed
companion trait or a separately reviewed application primitive at the call
site.

## Protocol Examples

### Bearer Token

```rust
use base64_ng::{
    STRICT_URL_SAFE_UNPADDED,
    secret::{SecretArrayFrame, SecretInput},
};
use base64_ng_subtle::SubtleSecretEq;

let mut frame = SecretArrayFrame::<32>::new(&STRICT_URL_SAFE_UNPADDED).unwrap();
frame
    .update(&SecretInput::new(b"AQEBAQEBAQEBAQEBAQEBAQ"))
    .unwrap();
let token = frame.finish().unwrap();
let expected = [1u8; 16];
let accepted = bool::from(token.subtle_ct_eq_public_len(&expected));
# let _ = accepted;
```

The decoded initialized length and final `accepted` value are public in this
example. The application must enforce its protocol's exact token length before
comparison when variable length is not permitted.

### MAC In Caller-Owned Storage

```rust
use base64_ng::secret::SecretOutput;
use base64_ng_subtle::SubtleSecretEq;

let mut storage = [0u8; 32];
storage[..16].copy_from_slice(&[0x5a; 16]);
let mac = SecretOutput::from_initialized(&mut storage, 16).unwrap();
let expected = [0x5a; 16];
let verified = bool::from(mac.subtle_ct_eq_public_len(&expected));
# let _ = verified;
```

`SecretOutput` still wipes its complete caller-owned range on drop. The
comparison does not transfer or declassify the bytes.

### Fixed-Width Key

```rust
use base64_ng::secret::SecretArray;
use base64_ng_subtle::SubtleSecretEq;

let key = SecretArray::<32>::from_array([0x42; 32], 32).unwrap();
let expected = [0x42; 32];
let equal = key.subtle_ct_eq_public_len(&expected);
assert!(bool::from(equal));
```

The protocol constructor enforces an initialized length of 32. Raw fixed-size
arrays can instead use `subtle_ct_eq_fixed_width` directly.

## Security Scope

This companion inherits `subtle`'s reviewed source-level intent, but it does
not claim formal compiler-level constant-time behavior for every target or
toolchain. Deployment evidence remains binary-, compiler-, target-, and
machine-specific. Length mismatch and the final `Choice` declassification are
outside the equal-length scan and are public.

Secret comparison does not authenticate surrounding protocol metadata, bind a
key to an algorithm, validate a MAC construction, or prevent replay. Those are
protocol responsibilities. Cleanup remains best effort and cannot erase
historical copies, registers, caches, swap, snapshots, or caller-owned input.

## Evidence

`scripts/check-2.0-subtle.sh` release-gates:

- equal, unequal, and public-length mismatch cases for every reviewed secret
  owner and view;
- no-default-feature, all-feature, release, clippy, and rustdoc builds;
- compile-fail cases for `PartialEq`, removed boolean sugar, and ordinary
  buffer use;
- the optimized non-inlined `subtle_ct_eq_public_len` assembly boundary and
  rejection of an emitted `memcmp`/`bcmp` call; and
- the isolated locked dudect harness build and deterministic fail-closed Welch
  statistic tests, including the reviewed equality content class.

The focused equality gate performs those locked build and deterministic tests
without refreshing network advisory data. Repository-wide CI, scheduled
security monitoring, and release gates run `scripts/check_dudect.sh`, which
adds RustSec and cargo-deny policy checks for the isolated harness lockfile.

Actual timing collection remains an explicit machine-local operation through
`BASE64_NG_RUN_DUDECT=1 scripts/check_dudect.sh`. Its result is empirical
evidence for that exact binary and machine, not a universal proof.
