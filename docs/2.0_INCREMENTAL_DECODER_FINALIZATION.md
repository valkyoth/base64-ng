# 2.0 Incremental Decoder Finalization

Status: implemented in Commit 11 and exposed in Commit 12 for the `2.0.0` candidate.

Commit 11 extended the heapless ordinary decoder with explicitly selected
strict unpadded RFC 4648 completion. Commit 12 exposes that state through the
validated `Base64<Spec>` surface. Padded and unpadded codecs share one bounded state model but
retain different, non-negotiable end-of-input policies.

## Selected Policies

- Strict padded codecs require the canonical `=` count. Finishing any partial
  quantum returns `TruncatedInput` at the absolute end position.
- Strict unpadded codecs forbid every `=` byte, including otherwise canonical
  or optional padding, and report `InvalidPadding` at its absolute index.
- An unpadded two-symbol tail produces one byte only when the second symbol's
  four unused bits are zero.
- An unpadded three-symbol tail produces two bytes only when the third symbol's
  two unused bits are zero.
- A one-symbol unpadded tail is an impossible encoded length and returns
  `InvalidLength`; it is distinct from padded truncation.
- Full four-symbol quanta have identical strict decoding behavior in both
  modes.

The padding mode is part of the sealed codec specification. The decoder never
guesses mode from input, accepts optional padding, or silently changes policy
at `finish`.

## Finalization And Retry

`finish(output)` validates a complete unpadded tail before writing caller
output. A malformed or noncanonical tail leaves that call's destination
unchanged and enters the absorbing failed state. A valid tail is decoded into
the fixed three-byte pending array and then drained into the destination.

When the destination is short, `OutputFull` reports a one-byte minimum. Every
retry with one output byte produces exactly one byte, consumes no additional
input, and cannot livelock. Completion is idempotent. Input after completion is
rejected until `reset`. Calling `update` after `finish` has begun is rejected as
`InputAfterFinish` even while final output remains pending; only another
`finish` call may drain that output. Reset begins one unrelated message at
source position zero.

## RFC 4648 Trace

The locked identifiers come from
[`rfc4648-requirements.json`](../rfc/rfc4648-requirements.json).

| Requirement | Commit 11 evidence |
|---|---|
| `RFC4648-3.2-MUST-PAD-BY-DEFAULT` | Strict padded mode continues to require canonical padding. Unpadded mode is an explicitly selected referring specification that omits padding. |
| `RFC4648-3.3-MUST-REJECT-NON-ALPHABET` | Unpadded mode rejects `=` and every other non-alphabet byte rather than treating padding as optional. |
| `RFC4648-3.3-MAY-IGNORE-EARLY-PADDING` | The strict unpadded decoder declines this option at every position. |
| `RFC4648-3.3-MAY-IGNORE-EXCESS-PADDING` | The strict unpadded decoder declines this option, including after a full quantum. |
| `RFC4648-3.5-MAY-REJECT-NONCANONICAL` | Every non-zero unused-bit value in two- and three-symbol tails is rejected at the final significant symbol's absolute index. |
| `RFC4648-4-24-TO-4X6` | All 64 one-symbol, 4,096 two-symbol, and 262,144 three-symbol alphabet tails are independently classified and decoded. |
| `RFC4648-4-PADDING-CASES` | Padded and explicitly unpadded RFC Section 10 vectors pass every source and destination partition. |
| `RFC4648-5-URL-SAFE-ALPHABET` | Standard and URL-safe unpadded modes run the same exhaustive finalization matrix with their exact alphabet. |

## Evidence

- Both unpadded RFC 4648 profiles pass every input and output partition.
- Deterministic bounded binary inputs are compared with the independent oracle
  over every partition.
- Every possible alphabet-only tail of length one, two, and three is checked.
- Every padding position, optional padded spelling, impossible length, and
  noncanonical final value is checked across every source partition.
- One-byte destinations and repeated zero-capacity retries prove bounded
  pending-output progress without source replay.
- Validated runtime alphabets use the same strict unpadded finalization.
- Debug, release, `no_std`, Rust 1.90.0, Clippy, and Kani gates exercise the
  finalization state machine.
