# 2.0 Tokio AsyncWrite Integration

Status: implemented in Commit 38 for the 2.0 companion package.

## Shared State

`EncoderWriter` and `DecoderWriter` accept `&Base64<S: Codec>` and own the
canonical `EncoderState` or strict `DecoderState`. The async layer retains only
the wrapped writer, a fixed output queue, poll lifecycle flags, and progress
counters. It contains no second Base64 quantum implementation.

Each `poll_write` drains earlier output before offering at most 768 raw encode
bytes or 1364 encoded decode bytes to the shared transformer. Those limits fit
the complete produced prefix in the fixed 1024-byte queue.

## Acceptance And Commitment

A `Ready(Ok(n))` write result means exactly `n` caller bytes were accepted by
the adapter. They are represented by retained incremental state or queued
output before the call returns. `Poll::Pending` accepts no new caller input.

`input_accepted` reports source bytes accepted by the adapter.
`output_committed` reports output bytes accepted by the wrapped writer. A short
inner write commits only its returned prefix. Pending output is never removed
until the wrapped writer reports that prefix accepted.

Output accepted by the wrapped writer is irrevocable. Cancellation cannot
retract it. Cancellation of a pending write, flush, or shutdown future leaves
the adapter alive with uncommitted state intact; polling the same adapter again
continues without replay or loss.

## Failure And Recovery

Ordinary inner write, flush, shutdown, and write-zero errors are retryable.
Queued output is retained and a later poll may retry it without transforming
accepted input again.

Malformed decode input, impossible transformer progress, counter overflow, an
output queue invariant failure, or an inner writer claiming more bytes than it
was given latches an absorbing failure and clears retained state. Failure
messages for malformed input expose only the stable redacted error class.

If delegated `poll_write`, `poll_flush`, or `poll_shutdown` panics and unwinding
is enabled, the adapter catches only to wipe local scratch, latch failure, and
clear retained state before resuming the original panic. Bytes accepted by the
wrapped writer before it panics remain irrevocable, but retry is prohibited so
they cannot be duplicated by this adapter. `panic=abort` remains a process-level
failure outside destructor and unwind cleanup guarantees.

`try_into_inner` succeeds only when no pending input or output would be
discarded. Unchecked `into_inner` remains an explicit escape hatch and may
discard accepted state. Direct writes through `get_mut` can reorder output and
are the caller's responsibility.

## Finalization And Plaintext

`poll_flush` drains complete output but does not finalize a partial Base64
quantum. `poll_shutdown` finalizes once, drains its output, flushes, and shuts
down the wrapped writer. A cancelled or failed downstream shutdown resumes
without re-emitting the final quantum.

`DecoderWriter` is an ordinary prefix-delivering API. Plaintext already
accepted by the wrapped writer remains exposed if a later encoded suffix is
malformed. No unbounded secret decoder writer is provided. Secret-bearing
frames must be bounded and fully validated before release through the core
`secrets` capability or an approved protected-memory companion.

## Cleanup And Evidence

Drop and terminal failure call the shared state's explicit best-effort cleanup
and clear the complete fixed output queue. They cannot clear caller buffers,
bytes already accepted by the wrapped writer, wrapped-writer copies, registers,
caches, swap, or crash dumps.

`scripts/check-2.0-tokio-writers.sh` enforces shared-state routing and runs:

- one-byte and arbitrary deterministic short-write/backpressure schedules;
- Standard padded and URL-safe unpadded parity against one-shot APIs;
- dropped pending write and shutdown futures followed by resume;
- write, write-zero, flush, and shutdown failure retries;
- malformed input, inner protocol over-reporting, and cleanup latching;
- panicking write, flush, and shutdown implementations after partial effects;
- checked inner recovery and accepted/committed progress checks;
- debug, release, clippy, rustdoc, and bounded Miri evidence.

This evidence checks the listed state transitions. It is not a formal proof of
every Tokio executor schedule or downstream writer implementation.
