# 2.0 Derive Hardening And Diagnostics

Commit 42 replaces the 1.x raw-array expansion in `base64-ng-derive` with a
declaration boundary built on the final 2.0 secret owners and sealed strict
codecs. The proc-macro crate remains dependency-free.

## Declaration Contract

`Base64Secret` accepts exactly one private `SecretArray<N>` tuple field and
requires one complete policy attribute:

```rust
use base64_ng_derive::Base64Secret;

#[derive(Base64Secret)]
#[base64_ng(
    alphabet = "standard",
    padding = "padded",
    exact_length = 32,
    exposure = "read"
)]
struct SigningKey(base64_ng::secret::SecretArray<32>);
```

The exact length must be an unsuffixed decimal integer from 1 through 1,024
and must equal the fully qualified `base64_ng::secret::SecretArray` capacity.
The fully qualified path prevents an unrelated lookalike type from satisfying
the macro's storage check. Generic structs, raw byte-array
fields, named fields, multiple fields, public fields, duplicate keys, unknown
keys, and incomplete policy declarations are rejected with stable
`Base64Secret:` diagnostics.

The `alphabet` and `padding` pair selects exactly one sealed codec:

| Alphabet | Padding | Codec |
|---|---|---|
| `standard` | `padded` | `STRICT_STANDARD_PADDED` |
| `standard` | `unpadded` | `STRICT_STANDARD_UNPADDED` |
| `url_safe` | `padded` | `STRICT_URL_SAFE_PADDED` |
| `url_safe` | `unpadded` | `STRICT_URL_SAFE_UNPADDED` |

No runtime codec, custom alphabet, forgiving parser, wrapped profile, or
legacy-whitespace policy can enter the generated secret path.

## Generated Secret Lifecycle

`decode_base64` accepts `SecretInput`, decodes through
`SecretArrayFrame<N>`, and commits a newtype only after fixed-work validation,
finalization, and the exact decoded-length check succeed. Rejected input leaves
no partially initialized returned owner. The frame and destination use the
core secret cleanup boundary.

`encode_base64` uses `SecretArrayEncoder` and returns an exactly sized
`SecretArray`. Encoded secret text is therefore still a wiping, redacted owner;
ordinary text requires a separate explicit exposure or declassification step.

The newtype stores `SecretArray<N>` directly. It inherits full-capacity
drop-time cleanup and cannot derive `Clone`, `Copy`, or ordinary equality from
that field. The macro generates redacted `Debug` and `Display`, exact length
constants, staged decode, and secret encode only. It does not generate an inner
owner recovery method because that would bypass `exposure = "none"`.

## Exposure Policy

Exposure is opt-in and method-based:

| Policy | Generated methods |
|---|---|
| `none` | no exposure method |
| `read` | `expose_secret` |
| `read_write` | `expose_secret`, `expose_secret_mut` |

Generated exposure returns `ExposedSecret` or `ExposedSecretMut`, not a raw
slice. The macro never generates `AsRef`, `AsMut`, `Deref`, `DerefMut`,
`FromStr`, `TryFrom<&str>`, `TryFrom<&[u8]>`, `PartialEq`, or an equality
helper. Use `base64-ng-subtle` for reviewed equality.

Rust privacy still permits code in the declaring module to access a private
tuple field directly. The derive prevents accidental public interoperability;
it cannot override source-level authority deliberately retained by the type's
own module.

## Evidence

`scripts/check-2.0-derive.sh` release-gates:

- all twelve alphabet, padding, and exposure-policy combinations;
- redacted formatting, exact-length rejection, strict codec selection, and
  secret-preserving encode/decode;
- stable diagnostics for malformed declarations and policy values;
- compile failures for raw-array storage, public fields, implicit exposure,
  cloning, ordinary equality, and ordinary string parsing; and
- source inspection excluding the 1.x CT facade, raw-array cleanup expansion,
  forbidden conversion traits, and generated equality sugar.

The core `SecretArray`, `SecretArrayFrame`, and `SecretArrayEncoder` cleanup,
fixed-work, and timing evidence remains authoritative for those delegated
operations. The derive does not create a stronger constant-time or
zeroization claim than the underlying exact build and deployment evidence.
