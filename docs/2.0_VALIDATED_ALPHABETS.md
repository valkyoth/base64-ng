# 2.0 Validated Alphabets

Status: Commit 5 value and constructor contract, integrated by Commit 6.

Commit 5 introduces the internal `ValidatedAlphabet` value used by the 2.0
codec core. It is deliberately not a public 1.3.9 API. Commit 6 integrates
validated alphabets into the private sealed 2.0 specification and codec
builders. Later operation commits carry that same owned value through
one-shot, incremental, in-place, formatting, and append surfaces before the
complete API is exposed at its planned checkpoint.

## Representation

A validated alphabet is exactly one owned `[u8; 64]`:

- no allocation;
- no `std` requirement;
- no function pointer, trait object, callback, or overridable mapping method;
- immutable after successful construction; and
- one table defines both encode and decode semantics.

The representation is `Copy`, `Send`, and `Sync`. Future incremental states can
therefore own the validated value without borrowing caller memory or executing
caller-provided mapping code.

## Construction

Const and runtime array construction use the same constructor:

```rust,ignore
const TABLE: [u8; 64] =
    *b"ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/";

const ALPHABET: ValidatedAlphabet = match ValidatedAlphabet::new(TABLE) {
    Ok(alphabet) => alphabet,
    Err(_) => panic!("invalid alphabet constant"),
};
```

Runtime byte slices are copied only after their length is proven to be exactly
64. Construction rejects:

- any length other than 64;
- bytes outside visible ASCII `0x21..=0x7e`;
- the reserved padding byte `=`;
- every duplicate byte, reporting its first and second positions.

An invalid const construction fails compilation when the caller promotes its
error branch to a const panic. `scripts/check-2.0-alphabet.sh` compile-tests a
valid const value and rejects duplicate, padding, non-visible, and wrong-length
constants.

## Mapping Contract

Ordinary encode and decode mappings are derived directly from the owned table.
The new core does not call the 1.x `Alphabet::encode` or `Alphabet::decode`
methods. Tests include a deliberately inconsistent legacy implementation and
prove that it cannot alter the new value's semantics.

The Commit 5 secret-semantic helper scans all 64 table entries through
crate-owned code. This establishes the custom-alphabet mapping shape only. It
does not make a complete constant-time claim: Commit 20 owns optimizer
barriers, the final result gate, generated-code evidence, and the documented
timing boundary.

## Evidence Split

Deterministic tests exhaust:

- all 2,016 duplicate-position pairs;
- every forbidden byte at every table position;
- all slice lengths from 0 through 65;
- all 256 encode inputs and all 256 decode bytes; and
- Standard, URL-safe, const custom, runtime-array, and runtime-slice mappings.

Kani separately quantifies over every valid constructor position and proves
that the per-position validator cannot index outside the table, overflow its
scan cursor, or return an out-of-range diagnostic index. This focused proof is
intentional: symbolically expanding the complete nested uniqueness matrix adds
solver cost without replacing the exhaustive semantic tests.

Run the checkpoint evidence with:

```sh
scripts/check-2.0-alphabet.sh
BASE64_NG_ALPHABET_TOOLCHAIN=1.90.0 scripts/check-2.0-alphabet.sh
cargo kani --no-default-features \
  --harness validated_alphabet_constructor_indexing_is_bounded
```
